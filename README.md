# Розподілена система обчислень

Вебзастосунок для виконання трудомістких обчислювальних задач із балансуванням
навантаження, чергою, автомасштабуванням і панеллю адміністратора.

**Задача:** розв'язання двовимірного рівняння Пуассона `−Δu = f` на одиничному
квадраті з нульовими граничними умовами Діріхле — метод скінченних різниць +
ітераційна схема SOR (successive over-relaxation).

## Швидкий старт

```bash
npm install
npm start
```

Відкрити **https://localhost:8443**

> Сертифікат самопідписаний. Браузер покаже попередження — натисніть
> «Додатково» → «Перейти на localhost (небезпечно)».
> Щоб прибрати попередження назавжди:
> `certutil -addstore -user Root certs\cert.pem`

### Запуск із GitHub

**Варіант 1 — GitHub Codespaces (найпростіше, нічого не встановлювати):**

1. Відкрити https://github.com/Valerysus/web
2. Кнопка **Code** → вкладка **Codespaces** → **Create codespace on main**
3. Зачекати ~1 хв: `npm install` і `npm start` виконаються автоматично
4. У вкладці **Ports** знайти порт `8443` → натиснути іконку глобуса
5. Браузер відкриє застосунок (посилання буде `https://<ім'я>-8443.app.github.dev`)

**Варіант 2 — локально з клонуванням:**

```bash
git clone https://github.com/Valerysus/web.git
cd web
npm install
npm start
```

**Варіант 3 — Docker:**

```bash
git clone https://github.com/Valerysus/web.git
cd web
docker compose up --build
```

## Архітектура

```
   браузер ──HTTPS──┐
   браузер ──WSS────┤
                    ▼
        ┌───────────────────────────────────┐
        │  Балансувальник (LB)  :8443       │
        │  TLS + Express + WebSocket        │
        │  черга задач · автомасштабування  │
        └────────┬───────────────┬──────────┘
                 │               │
        ┌────────▼──────┐ ┌──────▼────────┐
        │  app-1 :9101  │ │  app-2 :9102  │   … app-N (до MAX)
        │  worker_      │ │  worker_      │
        │  threads      │ │  threads      │
        └────────┬──────┘ └──────┬────────┘
                 │               │
                 └───────┬───────┘
                         ▼
              ┌─────────────────────────┐
              │  SQLite (WAL)           │
              │  users · jobs · events  │
              └─────────────────────────┘
```

| Компонент | Файл | Роль |
|---|---|---|
| Балансувальник | [src/lb.js](src/lb.js) | HTTPS/WSS, REST API, черга, планувальник, автомасштабування |
| Пул серверів | [src/pool.js](src/pool.js) | запуск/зупинка процесів, вибір найменш завантаженого, health-check |
| Сервер застосунку | [src/worker.js](src/worker.js) | приймає задачу, виконує у `worker_threads` |
| Обчислювальне ядро | [shared/solver.js](shared/solver.js) | метод скінченних різниць + SOR |
| БД | [src/db.js](src/db.js) | схема, журнали подій |
| Frontend | [public/](public) | SPA без збірки: задачі, стан системи, адмінпанель, архітектура |

## Виконання вимог ТЗ

| Пункт | Реалізація |
|---|---|
| **1. Обмеження трудомісткості** | Валідація на клієнті (живий індикатор бюджету) + повторна на сервері: невідомих ≤ 250 000, ітерацій ≤ 20 000, `невідомі × ітерації` ≤ 600 млн, таймаут 60 с. Перевищення → HTTP 422 з поясненням |
| **2. Прогрес виконання** | WebSocket (WSS): відсоток, етап, номер ітерації, максимальна зміна за ітерацію — оновлення ~4 рази/с |
| **3. Історія / статус / скасування** | Таблиця `jobs`; ліміт 4 активних задач і 20 в історії на користувача; скасування через `cancel_flag` + `worker.terminate()` || **4. Авторизація + HTTPS** | JWT (12 год) + bcrypt, TLS-сервер, WSS, CSP-заголовки |
| **5. Балансування ≥ 2 серверів** | Пул процесів `app-1…app-N`, вибір найменш завантаженого, health-check, перепризначення задач при падінні сервера |
| **6. Черга + ETA (+бали)** | Черга в БД, позиція та оцінка часу за середньою тривалістю задач |
| **7. Автомасштабування (+бали)** | scale-up при появі черги, scale-down після 45 с простою, межі `MIN_WORKERS`/`MAX_WORKERS` |
| **8. Панель адміністратора (+бали)** | Метрики, таблиця серверів, журнал подій, ручне керування пулом |

## Docker (альтернатива)

```bash
docker compose up --build
```

Файл [docker-compose.yml](docker-compose.yml) піднімає **один** контейнер із
балансувальником. Сервери застосунків — це не окремі контейнери, а дочірні
процеси Node (`fork()`), які балансувальник запускає всередині цього ж
контейнера. Для лабораторної цього достатньо: вимога «≥ 2 сервери
застосунків» виконується на рівні процесів, а не контейнерів.

Щоб отримати справжні окремі контейнери, потрібен окремий образ для
`src/worker.js` і сервіс із `deploy.replicas` — у поточній конфігурації
цього немає.

У цьому середовищі Docker відсутній, тому основний спосіб запуску —
`npm start`.

## Тести

```bash
npm test              # обчислювальне ядро (7 тестів)
npm run test:e2e      # smoke-тест API (система має бути запущена)
npm run test:isolation # ізоляція задач між користувачами
```

CI на GitHub Actions ([.github/workflows/ci.yml](.github/workflows/ci.yml))
перевіряє синтаксис, запускає тести ядра й піднімає систему для smoke-тесту.
